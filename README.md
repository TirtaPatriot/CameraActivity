# Activity Camera

Camera app for recording field activities (Android & iOS, Kotlin Multiplatform + Compose Multiplatform).
Photos are stamped with date-time, GPS coordinates, activity note and officer code; videos carry the same
metadata. Captures are stored locally and synced to a server: files to an Asustor NAS, metadata to SQL Server.

UI language: **Indonesian (default)** and English, switchable in Settings. Code, identifiers, folders,
database objects and API messages are in English.

## Structure

| Module | Contents |
|---|---|
| `model/` | Contract shared by app and server (`CaptureMetadata`, `UploadResponse`, API paths) |
| `shared/` | Shared Compose UI + logic: camera (`expect/actual`), location, stamp, local storage, sync |
| `shared/.../i18n/Strings.kt` | All user-facing text (`IndonesianStrings`, `EnglishStrings`) |
| `shared/src/androidMain` | CameraX, Fused Location, watermark via `Canvas` + GPS into EXIF |
| `shared/src/iosMain` | AVFoundation, CoreLocation, watermark via `UIGraphicsImageRenderer` |
| `androidApp/` | Android entry point (`MainActivity`, runtime permissions, launcher label id/en) |
| `iosApp/` | iOS entry point (SwiftUI); Xcode project generated by XcodeGen from `project.yml` |
| `server/` | Ktor API: upload → NAS, metadata → SQL Server |

## Data flow

1. The officer takes a photo/video → the file is saved in the app folder (`.../ActivityCamera/`) and recorded in `index.json` as **PENDING**.
2. In **Gallery**, the **Sync** button uploads captures one by one (multipart: `metadata` then `file`, streamed from disk).
3. The server stores the file at `STORAGE_ROOT/photo|video/yyyy/MM/dd/<clientId>.<ext>` and inserts a row into `dbo.activity_capture`.
4. `clientId` (UUID from the device) is unique → re-uploads never create duplicates.

## Requirements

- JDK 17+ and Android Studio (Narwhal or newer) with the Kotlin Multiplatform plugin
- For iOS: macOS + Xcode 16+, and `brew install xcodegen`

## Running

**Android**

```bash
./gradlew :androidApp:installDebug
```

**iOS**

```bash
cd iosApp
xcodegen generate
open iosApp.xcodeproj   # pick a Team under Signing, then Run on an iPhone
```

The Xcode build runs `./gradlew :shared:embedAndSignAppleFrameworkForXcode` automatically.
The camera is not available in the Simulator — test on a physical device.

**Server**

1. Mount the Asustor NAS share on the server host (NFS or SMB), e.g. at `/mnt/nas/activity-camera`, writable by the server process user.
2. Run `server/sql/001_init.sql` on the target SQL Server database.
3. Copy `server/.env.example` and provide the values as environment variables.
4. Run:

```bash
./gradlew :server:run              # development
./gradlew :server:buildFatJar      # → server/build/libs/activity-camera-server.jar
java -jar server/build/libs/activity-camera-server.jar
```

The server refuses to start if the NAS is not writable or the database is unreachable.

5. In the app, open **Settings** (Pengaturan): enter the server address (e.g. `http://192.168.1.10:8080`), API key and officer code.

## API

Every endpoint except `/health` requires the `X-Api-Key` header.

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Liveness check |
| `POST` | `/api/v1/captures` | Multipart upload: `metadata` (JSON) + `file` |
| `GET` | `/api/v1/captures?from=2026-11-01&to=2026-11-30&userCode=..&limit=100` | List metadata (dates in WIB) |
| `GET` | `/api/v1/captures/{id}/file` | Download the original file from the NAS |

## Adding a language

Implement `Strings` in `i18n/Strings.kt`, add an entry to `AppLanguage`, map it in `stringsFor()`,
then add the launcher label (`androidApp/src/main/res/values-xx/strings.xml`) and
`iosApp/iosApp/xx.lproj/InfoPlist.strings`.

## Notes & not yet implemented

- **Video stamp** is not burned into the video frames yet (needs transcoding: Media3 Transformer / `AVVideoComposition`). For now the stamp is shown on screen while recording and stored as metadata.
- **Sync** is manual from the Gallery; automatic background sync (WorkManager / BGTaskScheduler) is not implemented.
- **Authentication** is a shared API key; per-user login (JWT) is recommended for many officers.
- **Gallery** is a list without thumbnails.
- The app allows HTTP (cleartext) for an internal-network server; tighten this once the server uses HTTPS.
- Library versions are pinned in `gradle/libs.versions.toml`.

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs on every push to `main` and on pull requests:

- **android-and-server** (Ubuntu): builds the debug APK and the server fat JAR, uploaded as workflow artifacts.
- **ios** (macOS): builds the shared framework and the iOS app for the Simulator, unsigned.

Note: on private repositories macOS minutes are billed at a higher rate than Linux.
